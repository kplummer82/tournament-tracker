# Learn / marketing screenshot pipeline

Everything in `public/learn/` (guide screenshots + the deck PDF) is generated
from a **fictional demo world** — never from real rosters, so no real player
names or numbers ever appear in marketing assets.

## The demo world (dev DB)

Maple Valley Youth Baseball → Grizzly division → Spring 2026 → six invented
teams. The Thunderhawks carry the full fictional 12-player roster; demo game
is Thunderhawks vs River Otters with confirmations, batting order, a
defensive lineup in the fairness-warning state, and both rules on.
Entity ids live in `demo-ids.json` (regenerated by the seed script).

## Commands (dev server must be running on :3000)

```bash
# One-time per database: create the demo world (bails if it already exists)
node scripts/learn-capture/seed-demo.js

# Re-capture every screenshot (both themes, dev badge hidden) into public/learn/
node scripts/learn-capture/capture-learn.js
```

`capture-learn.js` logs in as the admin fixture (`admin@test.stackedbench.com`)
and shoots every guide image twice: dark = base name (`roster.png`),
light = `-light` suffix (`roster-light.png`). `ThemedImage` in the app picks
the variant matching the viewer's theme. It also captures the deck-only
extras and renders the lineup-card PDF page.

## Rebuilding the deck (docs/defensive-lineup-guide.*)

The deck pulls its images from sibling `deck-*.png` files. Map them from the
fresh captures, then build + flatten:

```bash
# from public/learn → deck names: roster→deck-01-roster, positions→deck-02-positions,
# confirmations→deck-03, batting-order→deck-04, defense-grid→deck-05,
# defense-picker→deck-06, defense-duplicate→deck-07, defense-warnings→deck-08,
# deck-bench→deck-09, deck-banner→deck-10 (unused), game-overview→deck-11,
# lineup-card→deck-13
node scripts/learn-capture/build.js      # deck-template.html + images → defensive-lineup-guide.html
node scripts/learn-capture/flatten.js    # slides → image-per-page PDF (fast to scroll)
# copy the outputs to docs/ and public/learn/defensive-lineup-guide.pdf
```

`topdf.js` is the vector-PDF variant (selectable text, heavier to render).

## Rules of the road

- Screenshots are static assets: committing them ships them to every
  environment. The demo world does NOT need to exist on LDQA/prod.
- Never point the capture at real team pages — fictional data only.
- Don't run `npm run build` while the dev server is up (corrupts `.next`).
